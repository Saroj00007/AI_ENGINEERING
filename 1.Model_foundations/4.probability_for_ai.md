# Chapter 4 — Probability for AI

We are **not** going to relearn probability. You already know the mathematics.

Our goal is to understand:

> **How does a model turn its numerical outputs into probabilities, and how are those probabilities used to make decisions or generate tokens?**

This is especially important because it directly prepares us for **LLMs in Phase 2**.

---

## 1. Why do we need probability?

Suppose a model receives:

> `"The cat is sitting on the ___"`

The model could consider:

```text
mat
0.45

floor
0.25

chair
0.15

table
0.08

...
```

These numbers represent the model's **belief distribution** over possible next tokens.

The model isn't simply saying:

> "The answer is mat."

Internally, it can produce scores for many possible tokens.

Conceptually:

```text
Context
   ↓
Neural network
   ↓
Scores for possible tokens
   ↓
Probability distribution
   ↓
Choose/sample token
```

This distinction between **scores** and **probabilities** is important.

---

# 2. Logits

The raw output of a model before converting it into probabilities is commonly called a **logit**.

Imagine the model produces:

```text
mat      → 4.2
floor    → 3.5
chair    → 2.8
table    → 1.1
```

These are **not probabilities**.

Notice:

```text
4.2 + 3.5 + 2.8 + 1.1 ≠ 1
```

So they cannot directly represent a probability distribution.

They're simply scores indicating how strongly the model favors different outcomes.

---

# 3. Softmax

We can convert logits into probabilities using **softmax**.

The formula is:

$$
P_i=\frac{e^{z_i}}{\sum_j e^{z_j}}
$$

You already know the mathematics.

The AI interpretation is what matters:

> **Softmax converts a collection of arbitrary scores into a probability distribution whose values sum to 1.**

For example:

```text
Logits:

mat      4.2
floor    3.5
chair    2.8
table    1.1

        ↓ softmax

Probabilities:

mat      0.55
floor    0.27
chair    0.12
table    0.06
```

The exact values here are illustrative.

The important transformation is:

```text
logits
  ↓
softmax
  ↓
probabilities
```

---

# 4. Why not directly output probabilities?

Because neural networks naturally produce unconstrained numerical values.

A neuron might produce:

```text
-2.4
3.7
0.8
11.2
```

There's no requirement that those numbers:

* are between 0 and 1
* sum to 1

Softmax gives us a convenient way to transform them into a probability distribution.

---

# 5. Probability does NOT mean certainty

This is important for your Phase 0 understanding.

Suppose:

```text
cat → 0.60
dog → 0.25
bird → 0.10
fish → 0.05
```

The model isn't saying:

> "There is a 60% objectively correct chance that the answer is cat."

It's saying something closer to:

> **Given its learned parameters and the current context, the model assigns this relative probability to each possible outcome.**

This is a model-generated probability distribution.

It does **not automatically represent objective truth**.

That connects directly to our earlier discussion of hallucinations.

---

# 6. How does an LLM use this?

This is where probability becomes extremely important.

Suppose the input is:

> `"The capital of Nepal is"`

The model might produce a distribution such as:

```text
Kathmandu → 0.96
Pokhara   → 0.01
Lalitpur  → 0.01
...
```

The model selects a token.

Suppose it selects:

```text
Kathmandu
```

Now the context becomes:

```text
"The capital of Nepal is Kathmandu"
```

Then the model predicts the **next token**.

This repeats.

So:

```text
Context
  ↓
Logits
  ↓
Probabilities
  ↓
Token selection
  ↓
New context
  ↓
Logits
  ↓
Probabilities
  ↓
Token selection
  ↓
...
```

And that's how an LLM generates a sequence.

---

# 7. Greedy selection vs sampling

Suppose the model produces:

```text
A → 0.60
B → 0.30
C → 0.10
```

One strategy is:

### Greedy

Always select the highest probability:

```text
A
```

Another strategy is **sampling**.

The model samples according to the probability distribution, meaning:

```text
A → most likely
B → possible
C → less likely
```

So the output doesn't necessarily have to be the single highest-probability token every time.

This is one reason language generation can have variation.

---

# 8. Temperature

Temperature controls how much we alter the probability distribution's sharpness.

Conceptually:

### Lower temperature

Distribution becomes more concentrated:

```text
A → 0.90
B → 0.07
C → 0.03
```

More predictable.

### Higher temperature

Distribution becomes flatter:

```text
A → 0.50
B → 0.30
C → 0.20
```

More variation.

The important mental model:

> **Temperature affects the randomness/variation of token selection; it does not retrain or modify the model's learned knowledge.**

---

# 9. Connecting everything together

We've now built almost the complete conceptual pipeline:

```text
                 TRAINING
                    ↓
              Learned parameters
                    ↓
                   MODEL
                    ↓
                 INPUT
                    ↓
             Neural network
                    ↓
                  Logits
                    ↓
                Softmax
                    ↓
             Probability
              distribution
                    ↓
            Token selection
                    ↓
              Next token
                    ↓
           Repeat generation
```

And this connects directly back to Phase 0:

> **The model learned parameters during training. During inference, those parameters are used to produce logits, which can be converted into probabilities and used to select the next token.**

---

## One important correction to keep

Don't say:

> "The model calculates the probability of whether the answer is true."

Instead, think:

> **The model assigns probabilities to possible outputs/tokens based on its learned parameters and current context.**

That's a much more accurate mental model.
