# Phase 2 — LLM Internals

## Chapter 8: Next-Token Prediction & Text Generation

In Chapter 7, we assembled the Transformer architecture. Now we're going to understand **how a trained model actually generates a response, one token at a time**.

By the end of this chapter, you'll understand the generation loop, temperature, greedy decoding, sampling, top-k, top-p, and KV caching. We'll keep the math practical.

### Part 1 — What does next-token prediction actually mean?

Let's start with a simple sentence:

> The sun rises in the ...

Imagine that we give this text to a trained GPT model.

The model doesn't generate the entire sentence at once. Instead, it estimates which token should come next, given the preceding tokens.

Conceptually:

```text
Input: "The sun rises in the"
                  |
                  ▼
             GPT Model
                  |
                  ▼
       Scores possible next tokens
                  |
                  ▼
           Probability distribution
                  |
                  ▼
          Select the next token
                  |
                  ▼
               "east"
```

Here, `"east"` is an illustrative result, not a guaranteed prediction.

The model has now generated one token.

What happens next?

The generated token becomes part of the input context:

```text
Step 1:
Input:  The sun rises in the
Output: east

Step 2:
Input:  The sun rises in the east
Output: every

Step 3:
Input:  The sun rises in the east every
Output: morning
```

This example illustrates the process; the exact tokens depend on the model and decoding settings.

The key idea is that **each newly generated token becomes part of the context used to predict the next token**.

This is called *autoregressive generation*.

Let's break down that term:

* **Auto:** The model continues the process itself.
* **Regressive:** Each prediction is conditioned on the preceding sequence.

More formally, the model estimates:

$$
P(x_t \mid x_1,x_2,\ldots,x_{t-1})
$$

Don't worry about memorizing the notation. It means:

> Estimate the probability of the next token given all the tokens that came before it.

### Part 2 — Why is it called a language model?

A language model learns patterns from training data and uses them to assign probabilities to possible token sequences.

For example, consider:

> I drink a cup of ...

Depending on its training and the context, the model might assign relatively high probabilities to tokens such as `"tea"` or `"coffee"`.

But notice something important: the model isn't restricted to one correct answer. Several continuations can be plausible.

The model's job during generation is to produce a continuation using the probability distribution it has learned.

That is also why a language model can sometimes produce incorrect information. **A likely continuation isn't necessarily a factually correct continuation.**

The model's training objective and decoding process don't guarantee truth.

### Part 3 — Does GPT always select the most probable token?

No. This is where decoding strategies become important.

Suppose the model produces the following probabilities:

| Candidate | Probability |
| --------- | ----------: |
| coffee    |         50% |
| tea       |         30% |
| water     |         15% |
| juice     |          5% |

There are different ways to select the next token.

**Greedy decoding** always selects the candidate with the highest probability. Here, it selects `"coffee"`.

**Sampling** selects a token according to the probability distribution. `"Coffee"` is still more likely, but `"tea"` or another candidate could be selected.

Neither approach guarantees that the generated response will be correct or coherent. The overall quality depends on the model, context, and decoding process.
