By the end of this lesson, you'll understand why it exists, what it stores, how it works, and why it matters when building production AI applications.

---

## 1. The problem: Repeating computations

Imagine we prompt GPT with:

> The cat sat on the

Suppose the model generates the following continuation:

> mat near the window.

Let's look at the process one token at a time.

**Step 1: Predict the first token**

The model processes the input:

```text
The cat sat on the
```

It predicts:

```text
mat
```

The sequence becomes:

```text
The cat sat on the mat
```

**Step 2: Predict the next token**

The model now needs to predict the next token after `mat`.

Conceptually, it processes the updated sequence:

```text
The cat sat on the mat
```

It predicts:

```text
near
```

**Step 3: Predict another token**

The model uses the updated context:

```text
The cat sat on the mat near
```

It predicts:

```text
the
```

And the process continues.

### What's inefficient about this?

Remember our self-attention lesson.

When processing a sequence, each token produces representations used to calculate its **keys and values** for attention.

Without caching, a straightforward implementation could recompute these for the previous tokens at every generation step—even though those previous tokens haven't changed.

For example:

| Generation step | Sequence length | Previous tokens needing attention-related processing |
| --------------- | --------------: | ---------------------------------------------------- |
| Predict `mat`   |               5 | The 5 input tokens                                   |
| Predict `near`  |               6 | The 6 tokens, including the previous input tokens    |
| Predict `the`   |               7 | The 7 tokens, including previously processed tokens  |

This repeats work.

**The key observation:** When a new token is appended, the existing tokens don't change. We can reuse certain computations that have already been performed for them.

That's where KV caching comes in.

---

## 2. What does KV cache mean?

KV stands for:

* **K — Keys**
* **V — Values**

Remember self-attention?

Each Transformer attention layer calculates three things:

$$
Q=XW_Q,\qquad K=XW_K,\qquad V=XW_V
$$

Where:

* \(Q\) represents queries.
* \(K\) represents keys.
* \(V\) represents values.

In attention, queries interact with keys to determine how much attention to give different positions. The resulting attention weights are then used to combine values.

During autoregressive generation, previously processed tokens have already had their keys and values calculated.

**A KV cache stores those previously computed keys and values so the model can reuse them in subsequent generation steps.**

It doesn't store the final answer or the entire model's reasoning.

It stores intermediate numerical tensors needed for attention.

---

## 3. How does KV caching work?

Let's compare generation without and with caching.

### Without KV cache

Suppose the input is:

```text
The cat sat on the
```

To predict `mat`, the model processes the prompt.

Next, to predict `near`, a straightforward approach processes the expanded sequence again:

```text
The cat sat on the mat
```

This may recalculate keys and values for all previous tokens.

Then, to predict the following token, it repeats the process for the expanded sequence again.

```text
Prompt
  ↓
Calculate attention-related representations
  ↓
Predict "mat"
  ↓
Expanded prompt
  ↓
Recalculate previous tokens' keys and values
  ↓
Predict "near"
  ↓
Expanded prompt
  ↓
Repeat previous calculations
```

### With KV cache

The first prompt is processed, and the model computes and stores keys and values for its tokens.

```text
Prompt: "The cat sat on the"
              ↓
      Process prompt tokens
              ↓
       Calculate K and V
              ↓
        Store KV cache
              ↓
        Predict "mat"
```

Now the model has generated `mat`.

To predict the next token, it processes the new token and computes its new keys and values. It then adds those to the existing cache.

```text
Existing KV cache:
K, V for "The cat sat on the"
              +
New token: "mat"
              ↓
Calculate K and V for "mat"
              ↓
Append to the cache
              ↓
Use cached K and V plus new K and V
              ↓
Predict "near"
```

The process continues:

```text
Cached: "The cat sat on the mat"
                       +
                   New token
                       ↓
                 Update cache
                       ↓
              Predict next token
```

This way, the model can reuse previously computed keys and values instead of recalculating them for every earlier token.

### One important detail

A standard decoder-only Transformer maintains KV caches **for each attention layer**, not just one global pair of K and V for the entire model.

Each layer's cache stores the keys and values computed at that layer for the tokens processed so far.

Also, implementations vary. Some models use multi-query attention, grouped-query attention, or other optimizations that reduce the size of the cache.

---

## 4. Why can we reuse the old keys and values?

This is the most important conceptual question.

Suppose the model has already processed:

> The cat sat on the

Now we append:

> mat

Does the new token change the original input tokens?

No.

In a standard causal Transformer, each token can attend only to itself and earlier tokens. It cannot attend to future tokens.

Therefore, adding `mat` at the end doesn't change the attention computations that produced the earlier tokens' layer-specific keys and values.

Those old keys and values can be reused.

The new token needs its own key and value at each layer, and its query can attend to the cached keys and values of the previous tokens, along with its own.

Conceptually:

$$
\text{Attention for new token}
=
\text{Query}_{\text{new}}
\text{ attending to cached keys and values}
$$

This is why causal attention and autoregressive generation work so naturally with KV caching.

---

## 5. Does KV caching make the model faster?

Generally, yes—particularly when generating long sequences.

Without a cache, a straightforward generation loop may repeatedly calculate keys and values for earlier tokens.

With a cache, those computations can be reused.

This can reduce redundant computation and improve token-generation speed.

However, KV caching introduces a trade-off.

### The trade-off: Speed versus memory

The cache must store keys and values for previously processed tokens across the model's attention layers.

As the context grows, the cache usually grows too.

| Benefit                                       | Cost                                                   |
| --------------------------------------------- | ------------------------------------------------------ |
| Reuses previous key/value computations        | Requires additional memory                             |
| Can reduce redundant computation              | Longer contexts require larger caches                  |
| Can improve generation throughput and latency | Memory bandwidth and cache management become important |

This matters when serving large language models.

For example, if a model serves many users simultaneously, each active generation may need its own cache. Memory usage can become a major constraint.

AI engineers need to consider both **inference speed and memory consumption** when selecting models and designing serving infrastructure.

---

## 6. Does KV caching change the model's answer?

KV caching is intended to be a computational optimization, not a change to the model's learned behavior.

With a correct implementation, caching should produce the same logits as recomputing the relevant operations, apart from possible small numerical differences caused by implementation details.

The cache does not:

* Teach the model new information.
* Change its learned weights.
* Automatically improve factual accuracy.
* Decide which token should be generated.

It simply reuses computations.

**Remember this distinction:**

* **Model parameters** are the learned weights that define the model.
* **KV cache** contains intermediate key/value tensors for the current sequence.
* **Generated tokens** are the output produced during inference.

These are three different things.

---

## 7. Putting it all together

Let's review the complete generation loop.

```text
             INPUT PROMPT
                   ↓
          Tokenization + Embedding
                   ↓
            Transformer Layers
                   ↓
       Compute and cache K and V
                   ↓
          Final hidden representation
                   ↓
              LM Head → Logits
                   ↓
                 Softmax
                   ↓
             Token selection
                   ↓
            Append new token
                   ↓
       Compute K and V for new token
                   ↓
         Reuse the existing KV cache
                   ↓
             Predict next token
                   ↓
                  Repeat
```

This diagram is conceptual. In actual implementations, the prompt is commonly processed in a **prefill stage**, which computes representations and initializes the cache for the prompt. Subsequent tokens are generated in a **decode stage**, typically processing one new token per step while reusing the cache.

These stages are important in production inference systems because they have different performance characteristics.
