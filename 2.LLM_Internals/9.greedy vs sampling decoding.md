# Phase 2 — LLM Internals

## Chapter 8: Next-Token Prediction & Text Generation

### Part 3 — Greedy Decoding vs. Sampling

So far, we've learned that an LLM produces logits, converts them into probabilities, and selects a token.

Now comes an important question:

**If the model gives us a probability distribution, how do we decide which token to generate?**

The answer depends on the *decoding strategy*.

We'll study two fundamental strategies: **greedy decoding** and **sampling**.

---

## 1. Greedy decoding: Always choose the highest probability

Suppose GPT receives this prompt:

> I want to drink a cup of

After processing the prompt, the model produces this probability distribution:

| Candidate token | Probability |
| --------------- | ----------: |
| coffee          |         50% |
| tea             |         30% |
| water           |         15% |
| juice           |          5% |

With greedy decoding, the model selects the token with the highest probability.

In this example:

```text
coffee → 50%  ← Highest probability
tea    → 30%
water  → 15%
juice  →  5%
```

Therefore, the model selects `coffee`.

The generated text becomes:

> I want to drink a cup of coffee

But remember, the model generates one token at a time. Let's continue the process.

Suppose the next probability distribution looks like this:

| Candidate token | Probability |
| --------------- | ----------: |
| today           |         40% |
| every           |         35% |
| before          |         15% |
| after           |         10% |

Greedy decoding selects `today`.

The sequence now becomes:

> I want to drink a cup of coffee today

This example is illustrative; actual predictions depend on the model and its context.

### The advantage of greedy decoding

* Predictable selection when the model's output scores are unchanged.
* Simple and computationally inexpensive to implement.
* Useful when you want the highest-probability token at every step.

### The limitation

Greedy decoding makes a locally optimal choice at every step, but that doesn't guarantee the best overall sequence.

For example, selecting the highest-probability token now might lead to a less natural continuation later.

**Important:** The most probable next token doesn't necessarily produce the best complete response.

---

## 2. Sampling: Choose according to the probability distribution

Now imagine using the same initial distribution:

| Candidate token | Probability |
| --------------- | ----------: |
| coffee          |         50% |
| tea             |         30% |
| water           |         15% |
| juice           |          5% |

Instead of always choosing the highest-probability token, sampling uses the distribution to select a token.

For example, the model could select:

* `coffee` — probability 50%
* `tea` — probability 30%
* `water` — probability 15%
* `juice` — probability 5%

Each selection is random according to the specified probabilities, assuming ordinary categorical sampling.

Notice the difference:

**Greedy decoding:**

```text
Highest probability → Select that token
```

**Sampling:**

```text
Probability distribution → Randomly select according to it
```

The sampling process doesn't give every token an equal chance. A token with a 50% probability is more likely to be selected than one with a 5% probability.

### Why is sampling useful?

Imagine asking an LLM:

> Give me an idea for a fantasy story.

You may want a variety of creative possibilities rather than the same predictable continuation every time.

Sampling can introduce variation into the generated response.

For example, one generation might begin:

> A young wizard discovered a mysterious door beneath an abandoned library...

Another might begin:

> Every night, a dragon left a silver feather on the king's doorstep...

These are illustrative examples. Different outputs are possible because sampling can make different token selections.

Sampling doesn't guarantee creativity or quality, however. It can also produce incoherent or inappropriate text.

---

## 3. Why can the same prompt produce different responses?

Suppose you submit this prompt twice:

> Write a short story about a robot.

With sampling enabled, the model might select different tokens at certain steps.

```text
                  Same prompt
                      |
               Same model
                      |
              Similar probabilities
                 /          \
                /            \
          Selection A     Selection B
               |                |
          Generation A     Generation B
```

If sampling makes different choices, the resulting sequences can diverge.

Even if both responses start with the same token, a difference later in the sequence changes the context used for subsequent predictions.

That can lead to very different responses.

However, **sampling does not guarantee different outputs every time**. The same output can occur more than once.

Also, if a model uses greedy decoding with identical inputs and deterministic execution, its output will generally be the same. Some systems have additional sources of nondeterminism, so this isn't an absolute guarantee across all implementations.

---

## 4. How does temperature fit into this?

Remember our previous lesson on temperature.

Temperature changes the probability distribution derived from the logits. Sampling then uses that distribution to select a token.

Consider the conceptual pipeline:

```text
              Prompt
                |
                v
          Transformer
                |
                v
              Logits
                |
                v
        Apply temperature
                |
                v
           Probabilities
                |
                v
          Decoding strategy
             /       \
            /         \
         Greedy     Sampling
            |           |
            v           v
       Highest       Sample from
       probability   distribution
            |           |
            v           v
         Token       Token
```

Technically, temperature is usually applied to the logits before softmax, as we discussed earlier.

The practical distinction is:

* **Temperature** changes the distribution.
* **Greedy decoding** selects the highest-probability token.
* **Sampling** selects a token according to the distribution.

For example, increasing temperature generally makes sampling less concentrated around the highest-scoring tokens.

But if you're using greedy decoding, increasing temperature doesn't change which token has the highest logit. Therefore, the greedy selection remains the same, assuming no other processing changes the ranking.

---

## 5. One subtle but important point

You might wonder:

"If sampling can select a lower-probability token, doesn't that make the model worse?"

Not necessarily.

The best decoding strategy depends on the task.

| Situation                               | Potentially useful approach                                                       |
| --------------------------------------- | --------------------------------------------------------------------------------- |
| Predictable, consistent token selection | Greedy decoding                                                                   |
| Creative writing with variation         | Sampling                                                                          |
| Generating alternative ideas            | Sampling                                                                          |
| Strict structured output                | Greedy decoding may help, but constraints and validation are often more important |

These are starting points, not universal rules. Real systems may use beam search, constrained decoding, or other strategies depending on the task.

Neither greedy decoding nor sampling guarantees factual correctness.
