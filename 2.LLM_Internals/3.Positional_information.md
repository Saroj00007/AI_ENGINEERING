
# Phase 2 — Chapter 3: Positional Information

## 1. The problem: How does an LLM know word order?

Consider these two sentences:

**Sentence A:**

```text
The dog chased the cat.
```

**Sentence B:**

```text
The cat chased the dog.
```

Both contain essentially the same words, but their meanings are different.

In Sentence A, the dog is doing the chasing.

In Sentence B, the cat is doing the chasing.

**The order of the tokens matters.**

Now remember what we learned in Chapter 2.

Each token is converted into an embedding vector:

```text
Token ID
   ↓
Embedding lookup
   ↓
Embedding vector
```

Suppose we represent the tokens using these symbols:

```text
"The"     → E₁
"dog"     → E₂
"chased"  → E₃
"the"     → E₄
"cat"     → E₅
```

The model initially receives a sequence of embeddings:

```text
[E₁, E₂, E₃, E₄, E₅]
```

But here's an important question.

**Where is the information telling the model which token comes first, second, or third?**

The embedding lookup associates a vector with each token ID. By itself, that lookup doesn't explicitly encode the token's position in the sentence.

We therefore need a mechanism for providing positional information.

That's the problem positional encoding and positional embeddings help solve.

---

## 2. Why attention alone isn't enough

You might think:

"Can't attention figure out the order automatically?"

Let's understand why this is a problem.

Imagine we give a transformer these token embeddings:

```text
[A, B, C]
```

Self-attention compares token representations with one another and combines information from them.

However, **standard self-attention without positional information doesn't inherently distinguish the order of its input tokens**.

If we rearrange the inputs:

```text
[C, A, B]
```

the attention mechanism can rearrange its corresponding outputs in the same way, but it doesn't independently know that the original order was different.

This property is called *permutation equivariance*.

You don't need to memorize that term yet. Understand the intuition:

> Without positional information or another order-sensitive mechanism, standard self-attention has no explicit way to distinguish the original sequence order.

That is a problem for language because:

```text
Dog bites man.
```

and

```text
Man bites dog.
```

have different meanings.

We need to provide the model with information about position.

---

## 3. Approach 1: Learned positional embeddings

One approach is to give each position its own learned vector.

Imagine our sequence has five positions.

We could have a positional embedding table:

| Position | Positional vector |
| -------- | ----------------- |
| 1        | P₁                |
| 2        | P₂                |
| 3        | P₃                |
| 4        | P₄                |
| 5        | P₅                |

The model learns these positional vectors during training.

For a token at position 1, we have:

```text
Token embedding:    E₁
Positional embedding: P₁
```

We combine them through addition:

$$
X_1 = E_1 + P_1
$$

Likewise, for the second token:

$$
X_2 = E_2 + P_2
$$

The complete input becomes:

$$
X = E + P
$$

Here, \(E\) represents the token embedding matrix and \(P\) represents the positional embedding matrix.

The result is a sequence containing both token information and positional information.

### Let's visualize the idea

```text
                    TOKEN
                      │
                      ▼
               Token embedding
                      │
                      │
                      ▼
                 Add together ◄──── Positional embedding
                      │                    ▲
                      │                    │
                      │              Token position
                      ▼
              Position-aware input
                      │
                      ▼
                  Transformer
```

For example:

```text
Token: "dog"

Token embedding:
[0.2, 0.5, 0.1, 0.8]

Position 1 embedding:
[0.1, 0.0, 0.2, 0.1]

After addition:
[0.3, 0.5, 0.3, 0.9]
```

If the same token appeared at position 3, it would receive a different positional vector.

Consequently, its combined input representation would differ.

**Important:** These numbers are illustrative. Real positional and token embeddings can have thousands of dimensions in modern models.

Also, this isn't the only approach. Learned positional embeddings are one way to provide positional information, but modern transformers use other approaches too.

---

## 4. Approach 2: Sinusoidal positional encoding

The original Transformer paper introduced a different approach: sinusoidal positional encodings.

Instead of learning every positional vector, we calculate positional values using sine and cosine functions.

You may encounter equations like:

$$
PE(pos,2i)=\sin\left(\frac{pos}{10000^{2i/d}}\right)
$$

$$
PE(pos,2i+1)=\cos\left(\frac{pos}{10000^{2i/d}}\right)
$$

Don't worry about memorizing these equations.

The essential idea is that **position is represented using patterns of numerical values that vary with position**.

Different positions receive different encodings, giving the model information about the sequence order.

Why use sine and cosine?

Their patterns vary at different frequencies, providing a structured way to represent positions and relationships between them.

For our purposes, remember the distinction:

* **Learned positional embeddings:** The model learns positional vectors as parameters.
* **Sinusoidal positional encodings:** Positional values are calculated using fixed mathematical functions.

Both approaches provide positional information, but they do it differently.

---

## 5. Approach 3: Modern positional methods

You might wonder:

"Do modern LLMs still use these exact approaches?"

Not necessarily.

One important modern approach is **RoPE (Rotary Positional Embeddings)**.

RoPE incorporates positional information by rotating components of token representations used in attention.

Its design makes attention scores sensitive to the relative positions of tokens.

You don't need to understand the rotation mathematics yet.

For now, know that modern positional methods can integrate positional information differently from simply adding a learned positional vector to each token embedding.

We'll encounter RoPE when discussing Q, K, and V in the attention chapter.

## 6. Let's connect everything we've learned

Suppose our input is:

```text
The dog chased
```

Our tokenizer produces token IDs:

```text
[101, 245, 892]
```

The embedding table converts these IDs into vectors:

```text
101 → E₁
245 → E₂
892 → E₃
```

We now have:

```text
[E₁, E₂, E₃]
```

Next, we provide positional information.

Using learned positional embeddings as our example:

```text
E₁ + P₁
E₂ + P₂
E₃ + P₃
```

The transformer receives the resulting representations:

```text
Token IDs
    ↓
Token embeddings
    ↓
Combine with positional information
    ↓
Position-aware representations
    ↓
Self-attention
    ↓
Further transformer processing
```

Notice how each component solves a different problem.

| Component            | Its purpose                                                |
| -------------------- | ---------------------------------------------------------- |
| Tokenizer            | Breaks text into tokens                                    |
| Token IDs            | Identifies tokens                                          |
| Token embeddings     | Provides learned numerical representations of tokens       |
| Positional mechanism | Provides information about token positions or order        |
| Self-attention       | Allows tokens to incorporate information from other tokens |

This is the foundation we'll build on in the next chapter.
