# Phase 2 — LLM Internals

## Chapter 8: Next-Token Prediction & Text Generation

### Part 4 — Top-k and Top-p Sampling

In the previous part, we learned two ways to select the next token:

* **Greedy decoding:** Always selects the highest-probability token.
* **Sampling:** Selects a token according to the probability distribution.

Now, let's explore a problem with ordinary sampling.

Suppose a model produces this distribution:

| Candidate token | Probability |
| --------------- | ----------: |
| coffee          |         40% |
| tea             |         30% |
| water           |         20% |
| juice           |          8% |
| spaceship       |          1% |
| volcano         |        0.7% |
| bicycle         |        0.3% |

These probabilities sum to 100%.

Imagine the model is completing:

> I would like a cup of ...

The tokens `spaceship`, `volcano`, and `bicycle` are unlikely continuations in this context.

Ordinary sampling could still select one of them, although their probabilities are low.

**What if we could restrict sampling to a more suitable set of candidates?**

That's the basic idea behind **Top-k and Top-p sampling**.

---

## 1. Top-k sampling: Keep only the k highest-probability candidates

The letter \(k\) represents how many candidate tokens we keep.

Suppose we set:

$$
k=3
$$

The model retains only the three highest-probability candidates.

Before filtering:

| Candidate | Probability |
| --------- | ----------: |
| coffee    |         40% |
| tea       |         30% |
| water     |         20% |
| juice     |          8% |
| spaceship |          1% |
| volcano   |        0.7% |
| bicycle   |        0.3% |

After Top-k filtering:

| Candidate     | Original probability |
| ------------- | -------------------: |
| coffee        |                  40% |
| tea           |                  30% |
| water         |                  20% |
| ~~juice~~     |               ~~8%~~ |
| ~~spaceship~~ |               ~~1%~~ |
| ~~volcano~~   |             ~~0.7%~~ |
| ~~bicycle~~   |             ~~0.3%~~ |

Only three candidates remain.

However, notice that the remaining probabilities sum to 90%, not 100%.

Before sampling, the remaining probabilities are typically **renormalized** so that they sum to 1.

The resulting distribution becomes:

| Candidate | Probability after filtering and renormalization |
| --------- | ----------------------------------------------: |
| coffee    |                                           44.4% |
| tea       |                                           33.3% |
| water     |                                           22.2% |

Now sampling can select only `coffee`, `tea`, or `water`.

### What does changing k do?

**Small k:**

* Fewer candidate tokens.
* More restricted choices.
* Potentially less variety.

**Large k:**

* More candidate tokens.
* More possible continuations.
* Greater opportunity for lower-probability candidates to be selected.

For example:

* `k = 1` effectively leaves only the highest-probability candidate, making sampling equivalent to greedy selection after the filtering step.
* `k = 3` keeps the top three candidates.
* A larger `k` allows more candidates to participate.

Top-k doesn't determine which token will be selected. It determines which tokens are eligible for sampling.

---

## 2. Top-p sampling: Keep enough candidates to reach a probability threshold

Top-p is also called **nucleus sampling**.

Instead of specifying a fixed number of candidates, we specify a cumulative probability threshold.

Let's use the same distribution:

| Candidate | Probability | Cumulative probability |
| --------- | ----------: | ---------------------: |
| coffee    |         40% |                    40% |
| tea       |         30% |                    70% |
| water     |         20% |                    90% |
| juice     |          8% |                    98% |
| spaceship |          1% |                    99% |
| volcano   |        0.7% |                  99.7% |
| bicycle   |        0.3% |                   100% |

Suppose we set:

$$
p=0.90
$$

The model considers candidates in descending probability order until their cumulative probability reaches the threshold.

Here:

* `coffee` contributes 40%.
* Adding `tea` brings the total to 70%.
* Adding `water` brings it to 90%.

The nucleus therefore contains three candidates: `coffee`, `tea`, and `water`.

Sampling happens from this restricted set after renormalization.

### What if we choose p = 0.95?

Now the cumulative probability must reach at least 95%.

* `coffee`: 40%
* `coffee + tea`: 70%
* `coffee + tea + water`: 90%
* Adding `juice`: 98%

The retained candidates are now:

`coffee`, `tea`, `water`, and `juice`.

The model keeps four candidates instead of three.

**The key difference:** Top-p adapts the number of candidates to the probability distribution.

If the distribution is highly concentrated, Top-p may retain only a few candidates. If probability is spread across many candidates, it may retain more.

*Implementation note:* Top-p typically keeps the smallest highest-probability set whose cumulative probability reaches or exceeds the chosen threshold. Exact handling of boundary cases can vary between implementations.

---

## 3. Top-k vs. Top-p: What's the difference?

| Feature            | Top-k                        | Top-p                                                  |
| ------------------ | ---------------------------- | ------------------------------------------------------ |
| What you configure | Number of candidates         | Cumulative probability threshold                       |
| Candidate count    | Fixed, apart from edge cases | Adapts to the distribution                             |
| Example            | Keep the top 10 tokens       | Keep enough tokens to reach 90% cumulative probability |
| Main purpose       | Restrict the candidate set   | Restrict the candidate set adaptively                  |

Think of them this way:

**Top-k asks:** "How many candidates should remain?"

**Top-p asks:** "How much of the probability distribution should the candidates collectively cover?"

Both methods are commonly combined with sampling, and some generation systems allow them to be used together.

## 4. Where does temperature fit into this?

Let's connect all the techniques we've learned.

```text
                   Prompt
                     |
                     v
                Transformer
                     |
                     v
                   Logits
                     |
                     v
              Temperature
                     |
                     v
                  Softmax
                     |
                     v
              Probability distribution
                     |
                     v
              Top-k / Top-p filtering
                     |
                     v
            Renormalized probabilities
                     |
                     v
                  Sampling
                     |
                     v
              Selected next token
```

This is a conceptual pipeline; implementations can vary in the ordering and details of filtering and normalization.

Each technique has a distinct role:

* **Temperature:** Changes how concentrated the distribution is.
* **Top-k:** Limits the number of candidates.
* **Top-p:** Limits the candidate set according to cumulative probability.
* **Sampling:** Selects a token from the resulting distribution.

These techniques influence the generated text, but none guarantees correctness.

For example, removing low-probability candidates doesn't mean every remaining candidate is factually correct.

## 5. Practical example: Building an LLM application

Imagine you're building an AI writing assistant.

A user asks:

> Give me five unusual ideas for a science-fiction story.

You might experiment with:

* A moderately high temperature to encourage variation.
* Top-p sampling to restrict selection to a nucleus of likely candidates.

For a different task, such as generating structured output, you might use a lower temperature or greedy decoding along with constrained output formats and validation.

There is no universally best configuration. The right settings depend on the model, task, and desired behavior.

As an AI engineer, your job is to **evaluate these settings on the actual task**, rather than assuming one combination will always work best.
