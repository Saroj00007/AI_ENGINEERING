Your understanding is actually **very close to correct!** You've identified an important gap in the Transformer architecture: if the Transformer blocks are refining token representations, where does the actual prediction happen?

Let's fill that gap. We'll follow the data from the beginning to the final prediction, using a small numerical example.

# 1. First, your understanding is correct—with one small refinement

You said:

> Until the end of the Transformer, it is only refining the input token. Then where is that input used to get the predicted output?

Exactly! The Transformer blocks progressively transform the input token representations into contextual representations.

But here's the important distinction:

**The Transformer doesn't directly predict a word. It produces representations that the model uses to calculate a prediction.**

The prediction happens through two additional operations after the final Transformer block:

1. **Output projection (LM head):** Converts the final representation into a score for every token in the vocabulary.
2. **Token selection:** Uses those scores to choose the next token.

Let's understand this step by step.

# 2. Follow one example through the entire model

Suppose we give GPT this input:

> The cat sat on the

We want the model to predict the next token.

For simplicity, imagine our vocabulary contains only five possible tokens:

```text
["mat", "floor", "dog", "runs", "blue"]
```

A real language model has a much larger vocabulary, but five tokens will make the calculations easier to understand.

## Step 1: The input enters the Transformer

The text is tokenized, and the tokens are converted into embeddings with positional information.

For illustration, suppose the input contains five tokens:

```text
The → [0.2, 0.4, 0.1]
cat → [0.7, 0.3, 0.8]
sat → [0.1, 0.6, 0.5]
on  → [0.3, 0.2, 0.9]
the → [0.6, 0.5, 0.4]
```

These vectors are illustrative.

The Transformer receives a matrix containing all five representations.

```text
Input representations
          ↓
    Transformer 1
          ↓
    Transformer 2
          ↓
         ...
          ↓
    Transformer N
```

Each Transformer block transforms the representations using attention, feed-forward networks, and associated residual and normalization operations.

At the end, the model has a new representation for each input position.

Let's call the final matrix \(H\).

If our example uses a hidden dimension of 3:

$$
H\in\mathbb{R}^{5\times3}
$$

That means five token positions, each represented by three numbers.

**So far, no token has been selected as the next output.**

We're still producing representations.

---

# 3. The crucial step: Which representation does the model use?

This is the part you're missing.

Look at our input again:

> The cat sat on the

There are five token positions.

After the final Transformer block, the model has five contextual representations:

$$
H=
\begin{bmatrix}
h_1\\
h_2\\
h_3\\
h_4\\
h_5
\end{bmatrix}
$$

Each \(h_i\) is the final representation at one token position.

Conceptually:

| Position | Token | Final representation |
| -------- | ----- | -------------------- |
| 1        | The   | \(h_1\)              |
| 2        | cat   | \(h_2\)              |
| 3        | sat   | \(h_3\)              |
| 4        | on    | \(h_4\)              |
| 5        | the   | \(h_5\)              |

During ordinary next-token generation, the model uses **the final representation at the last input position**, \(h_5\), to predict the next token.

Why?

Because that position represents the model's processed information about the context available up through the last token.

Due to causal masking, the representation at that position can incorporate information from the preceding tokens as well as the current token, but not from future tokens.

So the next operation is:

$$
\boxed{h_5\rightarrow\text{Output Projection}}
$$

We've finally reached the point where the model calculates the scores for its possible next tokens.

One nuance: during training, the model also produces predictions at earlier positions. During inference, when generating the next token, we typically use the logits from the last position.

---

# 4. The output projection: Turning a representation into scores

Now imagine that our last hidden representation is:

$$
h_5=[0.8,\ 0.2,\ 0.5]
$$

Again, these numbers are hypothetical.

This vector contains the information the model has computed at the final position.

But it is not itself a word, nor is each dimension a score for a particular word.

We need a learned transformation that maps this vector to the vocabulary.

That's the job of the **output projection**, also called the **language-model head (LM head)**.

Suppose our vocabulary has five possible tokens:

```text
mat
floor
dog
runs
blue
```

The output projection maps the three-dimensional hidden representation to five scores.

Mathematically:

$$
\boxed{z=h_5W_{\text{out}}+b}
$$

Here:

* \(h_5\): final hidden representation.
* \(W_{\text{out}}\): learned output weight matrix.
* \(b\): optional bias, depending on the model.
* \(z\): vector of vocabulary scores, called **logits**.

The dimensions in our example are:

$$
(1\times3)(3\times5)=(1\times5)
$$

So:

$$
[0.8,\ 0.2,\ 0.5]
\quad\longrightarrow\quad
[z_1,z_2,z_3,z_4,z_5]
$$

Suppose the output projection produces these logits:

| Candidate token | Logit |
| --------------- | ----: |
| mat             |   4.2 |
| floor           |   2.8 |
| dog             |   1.1 |
| runs            |  -0.5 |
| blue            |  -1.2 |

These scores are illustrative, not actual GPT outputs.

**Notice what happened:** the final hidden representation was transformed into a score for every possible next token in our vocabulary.

The model can now compare candidates.

This is the missing connection in your understanding.

The hidden representation isn't discarded. It is the input to the output projection, which converts it into vocabulary logits.

---

# 5. Are logits the final prediction?

Not quite.

Logits are raw scores. They aren't probabilities.

For example, the model produced:

```text
mat    →  4.2
floor  →  2.8
dog    →  1.1
runs   → -0.5
blue   → -1.2
```

A softmax operation converts these logits into probabilities:

$$
P_i=\frac{e^{z_i}}{\sum_j e^{z_j}}
$$

For our hypothetical example, the probabilities would be approximately:

| Candidate token | Probability |
| --------------- | ----------: |
| mat             |       76.3% |
| floor           |       18.8% |
| dog             |        3.4% |
| runs            |        0.7% |
| blue            |        0.3% |

The percentages are illustrative and rounded.

The model now has a probability distribution over the possible next tokens.

A decoding strategy then determines which token to select. Depending on the configuration, the system might choose the highest-probability token or sample from the distribution.

In our example, if we select the highest-probability token, the next token is:

```text
mat
```

The generated text becomes:

> The cat sat on the mat

**That is where the next-token prediction becomes an actual output token.**

Strictly speaking, the model's output at the neural-network level is usually the logits. Softmax and decoding turn those scores into a selected token.

# 7. One final distinction: How does the model learn the output projection?

You might now wonder:

**Who decides that the final representation should produce a high score for `mat` rather than `dog`?**

The output projection's weights are learned during training, along with the rest of the model's trainable parameters.

During training, the model receives text examples and learns to predict the next token.

For example:

```text
Input:  The cat sat on the
Target: mat
```

The model calculates logits for the vocabulary. A loss function measures how well the prediction matches the target token.

Backpropagation computes gradients, and an optimizer updates the trainable parameters to reduce the loss.

The parameters involved in the Transformer blocks and output projection are adjusted through this training process.

The model isn't given a hand-written rule that says:

> Whenever the input is "The cat sat on the", output "mat".

Instead, it learns statistical patterns from its training data.

Also, `mat` isn't necessarily the only acceptable continuation. Depending on context, `floor`, `ground`, or another token might be plausible.

Training encourages the model to assign probabilities that fit the training data; it doesn't guarantee that every prediction will be correct.
