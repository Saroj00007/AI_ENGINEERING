# Phase 2 — LLM Internals

## Chapter 7: Transformer Architecture

### Part 1 — The Complete Transformer Architecture

Welcome back! Today, we're going to connect everything we've learned into one system.

So far, you've learned about tokenization, embeddings, positional information, self-attention, multi-head attention, FFNs, residual connections, and LayerNorm.

Now let's answer a bigger question:

**How do these components work together to turn input text into a useful prediction?**

## 1. The big picture

Imagine we give a GPT-style model this input:

> The cat sat on the

We want the model to predict what comes next. Perhaps it predicts `mat`.

At a high level, the process looks like this:

```text
Input text
    ↓
Tokenization
    ↓
Token IDs
    ↓
Token Embeddings
    ↓
Add Positional Information
    ↓
┌─────────────────────────────┐
│     Transformer Block 1     │
│                             │
│  Multi-Head Self-Attention  │
│             ↓               │
│  Feed-Forward Network       │
│                             │
│  + Residual Connections     │
│  + Layer Normalization      │
└─────────────────────────────┘
    ↓
┌─────────────────────────────┐
│     Transformer Block 2     │
│                             │
│  Multi-Head Self-Attention  │
│             ↓               │
│  Feed-Forward Network       │
│                             │
│  + Residual Connections     │
│  + Layer Normalization      │
└─────────────────────────────┘
    ↓
            ...
    ↓
┌─────────────────────────────┐
│    Final Transformer Block  │
└─────────────────────────────┘
    ↓
Final Hidden Representations
    ↓
Output Projection (LM Head)
    ↓
Logits for Vocabulary Tokens
    ↓
Probabilities
    ↓
Select the Next Token
```

This is a simplified conceptual diagram of a GPT-style decoder-only Transformer. Exact implementation details vary between models.

Let's understand why each stage exists.

## 2. Stage 1: Converting text into representations

Suppose the input is:

`The cat sat on the`

### Step 1: Tokenization

The tokenizer converts the text into tokens.

For illustration, imagine these tokens:

```text
["The", " cat", " sat", " on", " the"]
```

The actual tokens depend on the tokenizer. In particular, spaces can be part of tokens.

### Step 2: Token IDs

Each token maps to an integer ID:

```text
["The", " cat", " sat", " on", " the"]
                  ↓
[  45,    812,    204,  56,   45  ]
```

These IDs are illustrative, not actual IDs from a specific tokenizer.

Remember: **token IDs are identifiers, not meaningful numerical measurements.**

For example, token ID `812` doesn't mean the token is more important than token ID `45`.

### Step 3: Token embeddings

The model looks up a learned vector for each token ID.

Suppose the embedding dimension is 4 for our tiny example:

```text
"The"   → [0.2, 0.5, 0.1, 0.8]
" cat"  → [0.7, 0.3, 0.9, 0.2]
" sat"  → [0.1, 0.6, 0.4, 0.3]
" on"   → [0.5, 0.2, 0.7, 0.1]
" the"  → [0.3, 0.8, 0.2, 0.6]
```

These numbers are also illustrative.

We now have five token vectors.

Their combined representation has shape:

$$
X\in\mathbb{R}^{5\times4}
$$

Here:

* `5` is the sequence length.
* `4` is the embedding dimension.

In a real model, the embedding dimension could be hundreds or thousands.

### Step 4: Add positional information

The model also needs information about token positions.

For a learned positional embedding implementation, we can express the operation as:

$$
X_i=E_i+P_i
$$

where:

* \(E_i\) is the token embedding.
* \(P_i\) is the positional embedding.
* \(X_i\) is the resulting representation.

This helps distinguish tokens based on where they appear.

**Important nuance:** GPT models do not all implement positional information identically. Some use methods such as RoPE, which we mentioned earlier.

At this point, the input has been converted into position-aware representations.

But these representations haven't yet passed through the Transformer blocks.

That's what happens next.

---

## 3. Stage 2: Entering a Transformer block

This is the most important part of today's lesson.

A Transformer block takes a sequence of representations and transforms them.

Conceptually, it does two major jobs:

1. **Attention:** Allows token positions to gather information from other positions.
2. **Feed-forward processing:** Applies learned nonlinear transformations to the representations.

Residual connections and normalization support these operations.

Let's use a simplified block:

```text
Input representations
         │
         ▼
 Multi-Head Self-Attention
         │
         ▼
 Residual Connection
         │
         ▼
  Layer Normalization
         │
         ▼
 Feed-Forward Network
         │
         ▼
 Residual Connection
         │
         ▼
  Layer Normalization
         │
         ▼
Output representations
```

This diagram illustrates a Post-LayerNorm arrangement. Many modern GPT-style architectures use Pre-LayerNorm instead, so we'll discuss that distinction later.

### What happens to the five tokens?

Our input has five token representations:

$$
X\in\mathbb{R}^{5\times4}
$$

For illustration, suppose our attention operation uses two heads, each with a dimension of two.

Each head produces:

$$
5\times2
$$

The outputs are concatenated:

$$
(5\times2)+(5\times2)\rightarrow5\times4
$$

An output projection then mixes the concatenated features while preserving the overall shape:

$$
5\times4\rightarrow5\times4
$$

The result can be combined with the original input through a residual connection.

The FFN then transforms each token representation, potentially expanding the feature dimension temporarily before projecting it back to four.

After the block, we still have:

$$
\boxed{5\times4}
$$

The representation has changed, but the sequence length and model dimension remain the same.

This is a fundamental architectural property of a standard Transformer block: **it transforms the representations without changing the number of token positions or the model's hidden dimension.**

---

## 4. What changes after attention?

Let's make the information flow more intuitive.

Consider these tokens:

> The cat sat on the mat.

Initially, each token has an embedding derived from its token ID, combined with positional information.

During self-attention, each position can gather information from relevant earlier positions.

For example, the representation at `sat` might gather information from `The` and `cat`.

In a GPT-style model, causal masking prevents `sat` from attending to future tokens such as `mat`.

The resulting representation at `sat` can incorporate information from its own token and the permitted preceding context.

Then the FFN transforms that representation.

The result isn't simply the original embedding of `sat` anymore. It is a **contextualized representation** produced by the attention and FFN operations.

This is one reason a Transformer is much more powerful than a simple lookup table of token embeddings.

### One crucial clarification

Attention doesn't permanently assign a human-readable meaning to each token.

Instead, each layer computes new numerical representations. Across many layers, these representations can encode increasingly useful information for the model's prediction task.

We shouldn't assume that every layer has a simple, identifiable semantic role.

---

## 5. Stage 3: Why stack multiple Transformer blocks?

A single block can transform representations and exchange information between token positions.

Why not use just one?

Because stacking blocks allows the model to perform repeated rounds of processing.

Imagine a model with three blocks:

```text
Input representations
         ↓
Transformer Block 1
         ↓
Transformer Block 2
         ↓
Transformer Block 3
         ↓
Final representations
```

Each block receives the output of the previous block.

Mathematically, we can express this as:

$$
H_1=\operatorname{Block}_1(X)
$$

$$
H_2=\operatorname{Block}_2(H_1)
$$

$$
H_3=\operatorname{Block}_3(H_2)
$$

Therefore:

$$
H_3=
\operatorname{Block}_3
\left(
\operatorname{Block}_2
\left(
\operatorname{Block}_1(X)
\right)
\right)
$$

The output of one block becomes the input of the next.

Each block has its own learned parameters, even though the blocks generally share the same overall architectural pattern.

### An analogy

Imagine writing an essay.

* First, you identify the main subject.
* Next, you consider how the ideas relate.
* Then, you refine the relationships and incorporate additional context.

A Transformer also performs successive transformations, but it does so through learned numerical computations—not through a fixed sequence of human-designed reasoning steps.

The analogy is only meant to illustrate why multiple processing stages can be useful.

### Why does depth matter?

With multiple blocks, information can be transformed repeatedly.

A token can gather information from other tokens in one layer, and later layers can process the resulting contextual representations further.

However, deeper models are not automatically better in every situation. Their effectiveness also depends on training, data, architecture, optimization, and other factors.

---

## 6. Stage 4: What happens after the final Transformer block?

This is where many people misunderstand the architecture.

They assume the Transformer blocks directly output a word.

**They don't.**

The final block outputs numerical representations.

For our five-token input, suppose the final hidden-state matrix is:

$$
H\in\mathbb{R}^{5\times4}
$$

In a real model, the hidden dimension might be thousands rather than four.

The model then needs to convert these representations into scores for possible next tokens.

This is the job of the **output projection**, commonly called the language-model head or LM head.

### The output projection

Suppose the vocabulary contains 10,000 possible tokens.

Our illustrative model has a hidden dimension of four.

The output projection maps each four-dimensional token representation to 10,000 scores:

$$
W_{\text{vocab}}\in\mathbb{R}^{4\times10000}
$$

Applying it to all five positions gives:

$$
\underbrace{5\times4}_{\text{hidden states}}
\quad\times\quad
\underbrace{4\times10000}_{\text{output projection}}
\quad=\quad
\underbrace{5\times10000}_{\text{logits}}
$$

The result contains one score for every vocabulary token at every input position.

These scores are called **logits**.

The model can then convert the logits into probabilities using softmax.

During ordinary next-token generation, the model uses the logits associated with the final input position to determine the next token.

We'll study the full process—including probabilities, token selection, and generation—in Chapter 8.

For now, remember:

**Transformer blocks produce representations. The output projection converts those representations into vocabulary scores.**

That distinction is essential.

## 7. Putting the entire process together

Let's revisit our original input:

> The cat sat on the

Here is the complete conceptual flow:

| Stage                             | What happens?                                                             |
| --------------------------------- | ------------------------------------------------------------------------- |
| 1. Tokenization                   | Text is divided into tokens.                                              |
| 2. Token IDs                      | Tokens are mapped to integer identifiers.                                 |
| 3. Embeddings                     | IDs are mapped to learned vectors.                                        |
| 4. Positional information         | The model receives information about token positions.                     |
| 5. Transformer block 1            | Attention exchanges information; the FFN transforms representations.      |
| 6. Transformer blocks 2 through N | Representations undergo additional learned transformations.               |
| 7. Final representations          | The model produces a final hidden representation for each input position. |
| 8. Output projection              | The hidden representations are mapped to vocabulary logits.               |
| 9. Next-token prediction          | The final position's logits are used to select the next token.            |

Suppose the model selects `mat`.

The input becomes:

> The cat sat on the mat

To generate another token, the model processes the extended context and predicts again. Efficient implementations can reuse cached attention information instead of recomputing everything from scratch.

We will explore that process in Chapter 8.

One final nuance: this example illustrates inference, when a trained model generates text. During training, the model also compares its predictions against training targets and updates its parameters to reduce the loss.
