# Chapter 4: Self-Attention — How Tokens Understand Context

## 1. The fundamental problem

Consider this sentence:

> The animal didn't cross the street because it was too tired.

What does **"it"** refer to?

The animal.

Now consider:

> The animal didn't cross the street because it was too busy.

Depending on the context, we might interpret "it" differently.

To interpret a token correctly, a language model needs to consider the other tokens surrounding it.

This is the problem self-attention helps solve.

**Self-attention allows each token to gather relevant information from other tokens in the same input sequence.**

Let's understand how it works from first principles.

## 2. How does self-attention work?

Imagine we give a transformer this sentence:

> The cat chased the mouse.

After tokenization, embedding lookup, and incorporating positional information, we have a matrix of token representations.

Let's call it \(X\).

For simplicity, imagine each token is represented by a vector containing four numbers.

$$
X =
\begin{bmatrix}
- & \text{The} & -\\
- & \text{cat} & -\\
- & \text{chased} & -\\
- & \text{the} & -\\
- & \text{mouse} & -
\end{bmatrix}
$$

This is just a conceptual illustration; the actual matrix contains numerical vectors.

Each row represents one token.

At this point, each token has its initial representation, which includes information about its identity and position.

But we want the representation of each token to incorporate useful information from the surrounding tokens.

For example:

* `cat` should be able to gather information about `chased`.
* `chased` should be able to gather information about `cat` and `mouse`.
* `mouse` should be able to gather information about the action happening in the sentence.

**Self-attention provides a mechanism for doing this.**

To achieve this, the model creates three vectors for every token:

1. **Query (Q)**
2. **Key (K)**
3. **Value (V)**

Let's understand why we need each one.

---

## 3. Query, Key, and Value (Q, K, V)

Think of self-attention as a system for deciding what information each token should gather from other tokens.

### A. Query — What information am I looking for?

A query represents what a token is looking for when comparing itself with other tokens.

For example, the token `chased` might learn to look for information related to:

* Who performed the action?
* What was affected by the action?

These are intuitive examples, not literal English questions generated by the model.

### B. Key — What information can I match against?

A key represents information used to determine how relevant a token is to another token's query.

For example:

* `cat` may provide information useful for identifying who performed the action.
* `mouse` may provide information useful for identifying what was chased.

The model learns how queries and keys should interact during training.

### C. Value — What information can I contribute?

A value represents the information that a token makes available to other tokens through attention.

If `chased` pays attention to `cat`, the value associated with `cat` contributes to the updated representation of `chased`.

### The simplest way to remember them

| Component | Intuitive question                 |
| --------- | ---------------------------------- |
| Query     | What information am I looking for? |
| Key       | How relevant am I to that query?   |
| Value     | What information can I contribute? |

These are useful intuitions. In an actual transformer, Q, K, and V are learned numerical representations, not explicit questions or labels.

---

## 4. How does the model calculate Q, K, and V?

Here's where the neural network comes in.

We start with the input matrix \(X\), containing one representation per token.

The model has three learned weight matrices:

$$
W_Q,\quad W_K,\quad W_V
$$

It uses them to calculate:

$$
\boxed{Q=XW_Q}
$$

$$
\boxed{K=XW_K}
$$

$$
\boxed{V=XW_V}
$$

What does this mean?

The model transforms each token representation into three different representations.

* \(W_Q\) learns how to produce queries.
* \(W_K\) learns how to produce keys.
* \(W_V\) learns how to produce values.

These matrices contain trainable parameters. During training, optimization adjusts them so that the resulting representations become useful for the language-modeling task.

**Important:** The same \(W_Q\), \(W_K\), and \(W_V\) matrices are applied to every token in a given attention head. Each token produces its own Q, K, and V vectors because its input representation is different.

For example:

$$
x_{\text{cat}} \rightarrow
(q_{\text{cat}},k_{\text{cat}},v_{\text{cat}})
$$

$$
x_{\text{mouse}} \rightarrow
(q_{\text{mouse}},k_{\text{mouse}},v_{\text{mouse}})
$$

We now have everything needed to calculate attention.

---

## 5. How does a token decide which other tokens matter?

Suppose we're calculating the updated representation for `chased`.

Its query is:

$$
q_{\text{chased}}
$$

The model compares this query with the keys of all the tokens.

For example:

$$
s_{\text{chased,cat}}
=
q_{\text{chased}}\cdot k_{\text{cat}}
$$

The dot product produces a score indicating how well the query and key match.

We calculate similar scores for the other tokens.

| Token being queried | Token being compared | Attention score |
| ------------------- | -------------------- | --------------: |
| chased              | The                  |             0.2 |
| chased              | cat                  |             2.4 |
| chased              | chased               |             1.1 |
| chased              | the                  |             0.3 |
| chased              | mouse                |             2.0 |

*These are illustrative numbers, not actual model outputs.*

Here, `chased` has higher scores for `cat` and `mouse` than for `The`.

This means the query-key comparisons assign greater relevance to those tokens before the scores are normalized.

The scores don't automatically have semantic meanings like "subject" or "object." The model learns patterns that help it predict the next token.

### The mathematical operation

For token \(i\) and token \(j\):

$$
\boxed{s_{ij}=q_i\cdot k_j}
$$

The score tells us how strongly token \(i\)'s query matches token \(j\)'s key.

But there's a problem: these scores can have arbitrary magnitudes and aren't probabilities.

We need to normalize them.

---

## 6. Softmax — Turning scores into attention weights

Suppose the scores for a particular token are:

$$
[0.2,\ 2.4,\ 1.1,\ 0.3,\ 2.0]
$$

We apply the softmax function.

Softmax converts the scores into positive values that sum to 1.

$$
\operatorname{softmax}(s_i)
=
\frac{e^{s_i}}{\sum_j e^{s_j}}
$$

After softmax, we might get attention weights like:

$$
[0.04,\ 0.48,\ 0.13,\ 0.04,\ 0.31]
$$

Again, these are illustrative values.

Notice:

* `The`: 0.04
* `cat`: 0.48
* `chased`: 0.13
* `the`: 0.04
* `mouse`: 0.31

The weights sum to 1.

The model has now calculated how much each token should contribute to the updated representation of `chased`.

A higher weight means a greater contribution from that token's value vector.

**One important clarification:** These weights aren't necessarily a perfect explanation of what the model understands. They are part of the mechanism used to mix information.

---

## 7. The final step — Combining the Value vectors

We have:

* Attention weights telling us how much each token contributes.
* Value vectors containing the information each token can contribute.

Now we combine them using a weighted sum.

For the token `chased`:

$$
\boxed{
z_{\text{chased}}
=
\sum_j \alpha_{\text{chased},j}v_j
}
$$

Here, \(\alpha_{\text{chased},j}\) is the attention weight assigned to token \(j\).

Expanding this:

$$
\begin{aligned}
z_{\text{chased}}={}&
0.04v_{\text{The}}\\
&+0.48v_{\text{cat}}\\
&+0.13v_{\text{chased}}\\
&+0.04v_{\text{the}}\\
&+0.31v_{\text{mouse}}
\end{aligned}
$$

The result is a new vector representing `chased` after it has gathered information from the other tokens.

We call this a **contextualized representation**.

The same process happens for every token, producing a new matrix of contextualized representations.

So the token `chased` no longer relies only on its initial embedding. Its representation now incorporates information from the sentence.

---

## 8. The complete self-attention equation

Let's combine everything we've learned.

The standard scaled dot-product attention equation is:

$$
\boxed{
\operatorname{Attention}(Q,K,V)
=
\operatorname{softmax}
\left(
\frac{QK^\top}{\sqrt{d_k}}
\right)V
}
$$

Don't worry about memorizing it yet. Understand what each part does.

| Operation           | Purpose                                                   |
| ------------------- | --------------------------------------------------------- |
| \(QK^\top\)         | Calculate query-key similarity scores                     |
| \(\div \sqrt{d_k}\) | Scale the scores to help keep their magnitudes manageable |
| Softmax             | Convert scores into normalized attention weights          |
| Multiply by \(V\)   | Combine value vectors using those weights                 |

Here, \(d_k\) is the dimensionality of the key vectors.

Why divide by \(\sqrt{d_k}\)? When key/query vectors have many dimensions, their dot products can become large in magnitude. Large scores can make softmax very concentrated, resulting in less useful gradients. Scaling helps control this effect.

### One more crucial concept: Causal masking

GPT-style language models generate text by predicting future tokens. When predicting the next token, they must not use tokens that come later in the sequence.

For example, when processing:

> The cat chased the mouse.

the representation used to predict what comes after `The cat` must not leak information from `chased the mouse`.

GPT-style transformers therefore use **causal masking** in self-attention, preventing a position from attending to future positions.

We'll examine this more closely when we study next-token prediction and text generation.

---

## 9. What you should understand before moving on

The complete process is:

1. Start with position-aware token representations \(X\).
2. Calculate \(Q\), \(K\), and \(V\) using learned weight matrices.
3. Compare queries with keys to calculate attention scores.
4. Apply scaling and softmax to obtain attention weights.
5. Use those weights to calculate weighted sums of the value vectors.
6. Obtain contextualized representations for the tokens.

The central idea is:

**Self-attention allows a token's representation to incorporate information from other tokens, with the contribution from each token determined by learned query-key comparisons.**

This is one attention head. In the next chapter, we'll explore how transformers use multiple attention heads to learn different kinds of relationships simultaneously.
