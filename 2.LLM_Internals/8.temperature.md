# Phase 2 — LLM Internals

## Chapter 8: Next-Token Prediction & Text Generation

### Part 2 — Temperature: Controlling Randomness

Let's start with a question.

Suppose GPT receives this input:

> The weather today is

The model produces these probabilities:

| Next token | Probability |
| ---------- | ----------: |
| sunny      |         50% |
| cloudy     |         30% |
| rainy      |         15% |
| terrible   |          5% |

For now, these are illustrative probabilities.

**How can we make the model's output more predictable or more varied without retraining the model?**

One way is to adjust the **temperature** used during decoding.

### 1. What is temperature?

Temperature is a setting that controls how sharply or evenly the model distributes probability across candidate tokens.

* **Lower temperature:** Makes the distribution more concentrated around high-scoring tokens.
* **Higher temperature:** Makes the distribution more spread out, giving lower-scoring tokens a better chance of being selected.

Temperature does not retrain the model or change its learned parameters. It changes how the model's logits are converted into probabilities during generation.

### 2. How does temperature work?

Recall the process from our previous chapters:

```text
Input text
    ↓
Transformer
    ↓
Logits
    ↓
Softmax
    ↓
Probabilities
    ↓
Token selection
```

Temperature is applied **to the logits before softmax**.

The formula is:

$$
P_i=\frac{e^{z_i/T}}{\sum_j e^{z_j/T}}
$$

Where:

* \(z_i\) is the logit for a candidate token.
* \(T\) is the temperature.
* \(P_i\) is the resulting probability.

You don't need to memorize this formula. Focus on what changing \(T\) does.

Let's examine three cases.

### 3. Low temperature

Imagine setting the temperature to `0.2`.

The model's probability distribution becomes more concentrated around the highest-scoring candidates.

```text
Before temperature adjustment:
sunny   ██████████  50%
cloudy  ██████      30%
rainy   ███         15%
terrible█            5%
```

After applying a low temperature, the distribution might look like this:

| Token    | Illustrative probability |
| -------- | -----------------------: |
| sunny    |                      88% |
| cloudy   |                      10% |
| rainy    |                     1.8% |
| terrible |                     0.2% |

The values are illustrative; the exact results depend on the original logits.

If we sample from this distribution, `"sunny"` becomes much more likely.

**When might this be useful?**

* Structured responses
* Tasks where consistency is important
* Some extraction and classification-style generation tasks

However, low temperature does not guarantee factual accuracy or eliminate hallucinations.

### 4. High temperature

Now imagine setting the temperature to `2.0`.

The distribution becomes more even:

| Token    | Illustrative probability |
| -------- | -----------------------: |
| sunny    |                      36% |
| cloudy   |                      30% |
| rainy    |                      22% |
| terrible |                      12% |

Again, these are illustrative values.

The highest-scoring token still has the highest probability in this example, but the alternatives have become more competitive.

If we sample from this distribution, the model has more opportunity to select a less likely token.

**When might this be useful?**

* Creative writing
* Brainstorming
* Generating varied ideas
* Exploring alternative phrasings

A higher temperature can also produce less coherent or less appropriate text. More variation doesn't automatically mean better creativity.

### 5. What happens at temperature zero?

This requires an important distinction.

Mathematically, ordinary temperature-scaled softmax approaches a distribution concentrated entirely on the highest logit as \(T\) approaches zero from above, assuming a unique maximum.

But many APIs treat `temperature=0` as a special setting rather than literally calculating the formula with zero.

In practice, it is commonly associated with greedy or near-deterministic decoding, although exact behavior depends on the implementation.

Remember:

**Temperature controls the probability distribution; the decoding strategy determines how a token is selected from it.**

For example, if the system always uses greedy decoding, increasing temperature won't change which token has the highest logit. The token with the highest logit will still be selected.

Temperature has its clearest effect when sampling is used.

---

## 6. One important distinction: Temperature doesn't change what the model learned

Suppose a model has learned that `"sunny"` is more likely than `"terrible"` in a particular context.

Changing temperature does not update its weights or teach it anything new.

Instead, it changes how strongly the original differences between logits influence the resulting probabilities.

Think of it this way:

* **Training:** Learns the model's parameters.
* **Inference:** Uses the trained model to make predictions.
* **Temperature:** Adjusts the probability distribution during decoding.
* **Sampling:** Selects a token using that distribution.

These are different operations.
