# The complete journey: From your question to the answer

Here is the overall pipeline:

```text
You type: "Who are you?"
          |
          ▼
1. Tokenization
   Text → Token IDs
          |
          ▼
2. Token Embeddings
   Token IDs → Vectors
          |
          ▼
3. Positional Information
   Vectors + Position Information
          |
          ▼
4. Transformer Layers
   ├── Self-Attention
   │   ├── Calculate Queries (Q)
   │   ├── Calculate Keys (K)
   │   ├── Calculate Values (V)
   │   ├── Calculate Attention Scores
   │   ├── Apply Softmax
   │   └── Combine Value Vectors
   │
   ├── Residual Connection + Layer Normalization
   │
   ├── Feed-Forward Network
   │
   └── Residual Connection + Layer Normalization
          |
          ▼
5. Final Hidden Representation
          |
          ▼
6. Output Projection → Logits
          |
          ▼
7. Convert Logits into Probabilities
          |
          ▼
8. Select the Next Token
          |
          ▼
9. Append Token to the Sequence
          |
          ▼
10. Repeat Until the Answer Is Complete
          |
          ▼
"I am ChatGPT, an AI assistant created by OpenAI."
```

Now let's walk through each step.

# Step 1: Tokenization — Breaking down your question

You send:

> Who are you?

The tokenizer converts your text into tokens.

For illustration, imagine the tokenizer produces:

```text
["Who", " are", " you", "?"]
```

A real tokenizer might split the text differently.

Each token maps to an integer ID:

| Token  | Illustrative token ID |
| ------ | --------------------: |
| `Who`  |                  1842 |
| ` are` |                   527 |
| ` you` |                   921 |
| `?`    |                    30 |

Your input is now represented as:

$$
[1842,527,921,30]
$$

**Why do we do this?**

Because neural networks operate on numerical representations rather than directly processing ordinary text.

At this point, the model has token IDs. It hasn't yet performed self-attention.

---

# Step 2: Token Embeddings — Turning IDs into vectors

The model has a learned embedding matrix.

Imagine its shape is:

$$
V \times d
$$

where:

* \(V\) is the vocabulary size.
* \(d\) is the embedding dimension.

For example, suppose:

$$
V=50,000,\qquad d=4
$$

The embedding matrix would have the shape:

$$
50,000 \times 4
$$

**These dimensions are deliberately tiny for our example. Real LLMs generally use much larger representations.**

The token ID identifies a row in the embedding matrix.

For illustration, the lookup might produce:

$$
E_{\text{Who}}=[0.2,0.5,0.1,0.7]
$$

$$
E_{\text{are}}=[0.4,0.1,0.8,0.3]
$$

$$
E_{\text{you}}=[0.9,0.2,0.3,0.5]
$$

$$
E_{?}=[0.1,0.6,0.4,0.2]
$$

The resulting input matrix is:

$$
E=
\begin{bmatrix}
0.2&0.5&0.1&0.7\\
0.4&0.1&0.8&0.3\\
0.9&0.2&0.3&0.5\\
0.1&0.6&0.4&0.2
\end{bmatrix}
$$

Each row represents one token.

**Important:** These numbers are invented for illustration. Actual embedding values are learned during training.

But there is still a problem: these are token representations, and the model needs information about the sequence's order.

That's where positional information comes in.

---

# Step 3: Positional Information — Telling the model where tokens occur

Consider these two questions:

> Who are you?

> You are who?

They contain the same words but have different orders and meanings.

The model therefore needs a mechanism for incorporating positional information.

In one simplified approach, we add a positional vector to each token embedding:

$$
X_i=E_i+P_i
$$

For example:

$$
E_{\text{Who}}=[0.2,0.5,0.1,0.7]
$$

Suppose the positional vector is:

$$
P_1=[0.1,0.0,0.2,0.1]
$$

Then:

$$
X_{\text{Who}}
=
[0.2,0.5,0.1,0.7]
+
[0.1,0.0,0.2,0.1]
$$

Therefore:

$$
X_{\text{Who}}=[0.3,0.5,0.3,0.8]
$$

We perform the corresponding operation for the other tokens.

Now we have position-aware representations:

$$
X=
\begin{bmatrix}
x_{\text{Who}}\\
x_{\text{are}}\\
x_{\text{you}}\\
x_{?}
\end{bmatrix}
$$

This matrix enters the transformer layers.

Remember, this addition is one way to incorporate positions. Other architectures, including those using RoPE, handle positional information differently.

Now we reach the important part.

# Step 4: Self-Attention — How the tokens exchange information

Let's pause and understand the problem.

At this point, each token has an initial numerical representation that incorporates its identity and positional information.

But the representation of `Who` has not yet been updated through attention with information from `are`, `you`, and `?`.

We want each token to have the opportunity to gather useful information from the other tokens.

**Self-attention performs this information-mixing operation.**

Let's work through it.

## 4.1 Calculate Query, Key, and Value

The model has three learned weight matrices:

$$
W_Q,\quad W_K,\quad W_V
$$

It calculates:

$$
Q=XW_Q
$$

$$
K=XW_K
$$

$$
V=XW_V
$$

These matrices are transformations learned during training.

Every token representation is transformed into three vectors:

* Query: used to calculate relevance scores against other tokens.
* Key: used to determine how well a token matches another token's query.
* Value: contains information that can contribute to the updated representation.

For our question, imagine the tokens have these simplified representations:

| Token | Query   | Key     | Value   |
| ----- | ------- | ------- | ------- |
| Who   | \(q_1\) | \(k_1\) | \(v_1\) |
| are   | \(q_2\) | \(k_2\) | \(v_2\) |
| you   | \(q_3\) | \(k_3\) | \(v_3\) |
| ?     | \(q_4\) | \(k_4\) | \(v_4\) |

These are different learned transformations of the input representations.

The model doesn't explicitly ask itself an English question like "Who am I?" The Query, Key, and Value vectors are numerical representations used by the attention mechanism.

## 4.2 Calculate attention scores

Let's focus on the token `Who`.

Its query is \(q_1\).

The model compares it against the keys of all four tokens:

$$
s_{11}=q_1\cdot k_1
$$

$$
s_{12}=q_1\cdot k_2
$$

$$
s_{13}=q_1\cdot k_3
$$

$$
s_{14}=q_1\cdot k_4
$$

These calculations produce four scores.

For illustration, imagine the scores are:

| Token being queried | Token compared | Score |
| ------------------- | -------------- | ----: |
| Who                 | Who            |   1.2 |
| Who                 | are            |   0.5 |
| Who                 | you            |   2.4 |
| Who                 | ?              |   0.9 |

**These scores are hypothetical. They aren't actual attention scores from ChatGPT.**

The scores indicate how strongly the query matches each key before normalization.

Notice that `you` received the highest score in this example.

That doesn't mean the model explicitly understands the grammatical relationship in a human-like way. It means that, given its learned parameters and input, this query-key comparison produced the highest score.

## 4.3 Apply softmax

We now transform the scores into attention weights:

$$
\alpha=\operatorname{softmax}(s)
$$

Suppose the resulting weights are:

$$
\alpha=[0.16,0.08,0.59,0.17]
$$

They sum to 1.

This example assigns the greatest weight to `you`.

The weights determine how strongly each token's value contributes to the updated representation of `Who`.

## 4.4 Combine the value vectors

Now comes the part we discussed earlier.

The attention output for `Who` is:

$$
z_{\text{Who}}
=
0.16v_{\text{Who}}
+
0.08v_{\text{are}}
+
0.59v_{\text{you}}
+
0.17v_{?}
$$

The model multiplies each value vector by its attention weight and adds the resulting vectors.

The result is a new representation for `Who`.

That representation combines information from all four tokens, weighted by their attention scores.

**This is the key operation in self-attention: each token can produce a new representation by gathering information from other tokens.**

### What about the other tokens?

We don't perform attention only for `Who`.

We calculate the corresponding attention output for:

* `are`
* `you`
* `?`

Each token has its own query, which produces its own set of attention weights.

Consequently, each token can gather a different combination of information from the sequence.

The resulting matrix contains a contextualized representation for every token.

### A crucial detail: Causal masking

GPT-style models generate text from left to right.

During next-token prediction, a position must not use future tokens that it wouldn't have access to when generating text.

Causal masking prevents a token from attending to positions later in the sequence.

In our example, when the model is learning to predict the token after `Who`, it must not use information from the later tokens `are you?` to make that prediction.

For a standard causal language model, the attention mask prevents this future information from leaking into the prediction.

When processing the complete input `Who are you?`, earlier positions still cannot attend to later positions, but the final position can attend to all preceding positions.

That final position is particularly important when predicting the next token.

# Step 5: The transformer processes the attention output

Self-attention is not the entire transformer.

A typical transformer block also includes a feed-forward network, residual connections, and layer normalization.

A simplified structure looks like this:

```text
Input representations
        |
        ▼
Self-Attention
        |
        ▼
Residual Connection + Normalization
        |
        ▼
Feed-Forward Network
        |
        ▼
Residual Connection + Normalization
        |
        ▼
Output representations
```

Let's briefly understand the remaining components.

### A. Residual connections

A residual connection allows the block to preserve the input representation while adding the transformation's output.

A simplified illustration is:

$$
Y=X+\operatorname{Attention}(X)
$$

This equation omits normalization and some implementation details, but it illustrates the basic idea.

Residual connections help information and gradients flow through deep networks.

### B. Layer normalization

Layer normalization helps stabilize the values flowing through the network.

The exact placement of normalization depends on the architecture.

### C. Feed-forward network

The feed-forward network applies learned transformations to each token's representation.

Unlike self-attention, which mixes information between token positions, the feed-forward network primarily transforms each position's representation independently.

These components work together to improve the representations.

## What about multiple transformer layers?

A large language model contains many transformer blocks.

The output of one block becomes the input to the next.

```text
Input representations
        |
        ▼
Transformer Block 1
        |
        ▼
Transformer Block 2
        |
        ▼
Transformer Block 3
        |
        ▼
       ...
        |
        ▼
Final Transformer Block
```

Each block can refine the representations further.

Within each block, attention mixes information between tokens, while the feed-forward network transforms the resulting representations.

Our simplified diagram shows one attention operation at a time. Real transformer blocks commonly use **multi-head attention**, which we'll study next.

---

# Step 6: Convert the final representation into logits

We've now processed the question through the transformer.

The model has a final representation for each token.

For a causal language model, the representation at the final input position is used to predict the next token.

For our question:

> Who are you?

The final position corresponds to `?`.

The model takes the final hidden representation at that position:

$$
h_{\text{last}}
$$

It then applies an output projection:

$$
\boxed{\text{logits}=h_{\text{last}}W_{\text{out}}+b}
$$

This is a simplified expression; some models omit an explicit bias or share weights between the token embedding and output projection.

The output projection produces a score for every possible next token in the model's vocabulary.

These scores are called **logits**.

For illustration:

| Candidate next token | Logit |
| -------------------- | ----: |
| I                    |   8.2 |
| The                  |   3.1 |
| You                  |   2.4 |
| Banana               |  -1.5 |

These are hypothetical values.

A higher logit generally means the token receives a higher probability after applying softmax.

Notice that the model isn't yet outputting the entire answer.

It's preparing to predict **one next token**.

---

# Step 7: Convert logits into probabilities

We apply softmax to the logits:

$$
P(t_i)=\frac{e^{z_i}}{\sum_j e^{z_j}}
$$

Suppose the resulting probabilities look like this:

| Candidate token       | Illustrative probability |
| --------------------- | -----------------------: |
| I                     |                     0.85 |
| The                   |                     0.07 |
| You                   |                     0.05 |
| Other tokens combined |                     0.03 |

These numbers are only illustrative.

The model now has a probability distribution over its possible next tokens.

The token `I` has the highest probability in this example.

A decoding strategy selects the next token from this distribution. Depending on the generation settings, the model might select the highest-probability token or sample from a broader set of candidates.

Suppose it selects:

> I

Our sequence becomes:

```text
Who are you? I
```

But the answer isn't finished.

The model needs to generate more tokens.

---

# Step 8: Predict the next token again

The model now continues generating.

Suppose the next token is ` am`.

The sequence becomes:

```text
Who are you? I am
```

Then it predicts another token, perhaps ` ChatGPT`.

```text
Who are you? I am ChatGPT
```

Then perhaps:

```text
Who are you? I am ChatGPT, an AI assistant.
```

The actual tokenization might split these words into different pieces, and the actual output may differ.

The essential mechanism is the same: the model repeatedly predicts another token using the available context.

At each generation step:

1. The model processes the available context.
2. The final relevant hidden representation is projected into logits.
3. The logits are converted into probabilities.
4. The decoding method selects a token.
5. The selected token is appended to the sequence.

The process repeats until the model emits an end-of-turn or stopping token, or another stopping condition is reached.

**Important implementation detail:** Real systems often use a key-value cache to reuse attention computations from earlier tokens, instead of recomputing everything from scratch for each generated token.

---

# Step 9: The final answer

After enough iterations, the model might produce:

> I am ChatGPT, an AI assistant created by OpenAI.

Your application then presents the generated text to you.

That's the complete high-level journey.

# Let's connect everything back to self-attention

You originally asked how attention works inside an LLM.

Here's the key distinction between the stages:

| Stage                | What happens?                                                      |
| -------------------- | ------------------------------------------------------------------ |
| Tokenization         | Text becomes token IDs.                                            |
| Embedding            | Token IDs become learned vectors.                                  |
| Positional mechanism | Position information is incorporated.                              |
| Query, Key, Value    | The input representations are transformed into Q, K, and V.        |
| Attention scores     | Queries are compared with keys.                                    |
| Softmax              | Scores become attention weights.                                   |
| Weighted sum         | Value vectors are combined into contextualized representations.    |
| Transformer blocks   | Attention and feed-forward transformations refine representations. |
| Output projection    | The final representation becomes vocabulary logits.                |
| Decoding             | A next token is selected.                                          |
| Iteration            | The process repeats to generate more text.                         |

## The most important insight

**Self-attention does not directly decide which English word the model should output.**

Instead, it helps construct contextualized representations of tokens.

Those representations pass through the transformer and are used to calculate logits, which determine the distribution over possible next tokens.

The model generates text one token at a time.
